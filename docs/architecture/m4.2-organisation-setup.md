# M4.2: Client organisation setup

Status: proposed for review. Branch `feat/m4.2-organisation-setup`.

## What clients can do

| Area | Screens | Who (server-enforced) |
|---|---|---|
| Organisation | `/settings`: name, time zone, status, web address | Everyone in the organisation can view. Only roles with `tenant.settings.manage` across the whole organisation can edit. Status and web address are platform-only. |
| Sites | `/settings/sites`, `/settings/sites/new`, `/settings/sites/[id]`: name, code (auto-generated if blank), address, town, postcode, time zone; deactivate and reactivate | View: `site.view`, within its scope. Add: `site.manage` across the whole organisation. Edit, deactivate: `site.manage` for that site. |
| Teams | `/settings/teams`, `/settings/teams/new`, `/settings/teams/[id]`: name, site; deactivate and reactivate; members list | `team.manage` for the team's site (and for the new site, when moving a team) |
| People | `/people/new`, `/people/[id]/edit`: names, job title, employee number (auto `E0001` if blank), status (starting soon, active, left), start and leaving dates, main site, teams, work email and phone | `employee.manage` for the person's current and new site. A person with no site needs the permission across the whole organisation. |
| Dashboard | Real counts; empty-state checklist with links to add a site or people | Within scope |

**Data minimisation:** no dates of birth, national insurance numbers, home addresses, right-to-work evidence or documents. Employee records stay separate from logins: `membership_id` is never set or changed by this feature.

**No hard deletes:** sites and teams are deactivated, and people are marked "Left" with a leaving date. Team membership links are the only rows ever removed.

## Security

- **Server-only organisation context:** the organisation always comes from the server session (`getWorkspace()`), and every write runs inside `withTenant()`. Row-level security confines it to that organisation, and composite foreign keys reject links to other organisations' sites or teams.
- **Permission checks in every write function** (`src/lib/workspace/mutations.ts`): permission and site scope are checked in the function itself, so the tests exercise them directly. The pages hiding buttons is never the control.
- **Re-checked ids:** submitted ids are untrusted. Another organisation's or out-of-scope records return "not found". Teams outside your scope are never added, and are kept untouched when you edit a person.
- **Server actions:** POST-only, with Next.js Origin checks. Input is re-validated with the shared zod schemas (`src/lib/validation/organisation.ts`).
- **Least privilege (migration):** column-level `UPDATE` on `tenant` (name and time zone only) and on `employee` (never `tenant_id`, `id`, `membership_id` or `created_at`).
- **Audit:** not available yet. The audit foundation (M3.2) isn't built, so changes aren't audited in this increment. It's listed as a follow-up.

## Database change: `20261020120000_organisation_setup`

- `site`: add `address_line`, `town` and `postcode` (nullable, with length checks).
- `employee`: add `job_title` (nullable, at most 100 characters).
- `teamhappi_app`: revoke table-level `UPDATE` on `tenant` and `employee`, then grant it back column by column.

It's additive. No data is changed. Rollback steps are at the end of the migration file.

## Tests

- **Database security, as the real app role** (`tests/security/organisation-setup.test.ts`):
  - create and update for sites, teams and people;
  - duplicates and invalid input;
  - other organisations;
  - site-scoped HR manager, site manager and worker;
  - column privileges;
  - archiving, not deleting;
  - team edits that keep out-of-scope teams;
  - dashboard and People accuracy;
  - a suspended membership can't write.
- **Browser** (`tests/e2e/organisation-setup.spec.ts`, desktop and mobile, with axe accessibility scans):
  - the full owner workflow (site, then deactivate and reactivate, team, duplicate, person, edit validation, dashboard count);
  - limits for a site-scoped manager and a worker.
