- **The column is nullable.** Existing invitations keep working and behave exactly as before.

## Rollback considerations

- **While no invitation has an `employee_id`**, the migration can be reversed with the statements in its header comment, restoring the M6 function. That would be a separately approved, reviewed run.
- **Once records have been linked**, fix forward. Removing the column doesn't undo links, which are ordinary data.
- **Code rollback without a database rollback is safe:** the older code never sets `employee_id`, and the function behaves as M6 for those invitations.
